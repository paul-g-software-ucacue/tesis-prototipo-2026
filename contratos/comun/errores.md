# Catálogo de códigos de error

Cada código es estable y no depende del texto ni del mensaje de una excepción (principio XIII). El esquema `Error` está en [errores.yaml](errores.yaml).

| Código | Estado | Título | Descripción | Cuándo |
|---|---|---|---|---|
| `SEGURIDAD_NO_AUTENTICADO` | 401 | Sesión no válida | Inicia sesión de nuevo para continuar. | Petición a la API sin token, o con un token alterado, vencido, mal formado, firmado con otra llave, con otro algoritmo o de otro emisor. Lo responden el API Gateway y los 4 procesos, siempre con el mismo cuerpo, sin decir qué falló (ADR-014). |
| `SEGURIDAD_ACCESO_NO_AUTORIZADO` | 403 | Acceso no autorizado | No tienes permiso para esta acción. Si crees que deberías tenerlo, pide al administrador que revise tus roles. | Token válido sin el permiso de la operación, un token de usuario en `/interno/**` o un token de proceso fuera de él. Lo responden los 4 procesos y el API Gateway, siempre con el mismo cuerpo, sin decir qué permiso faltó (ADR-021). |
| `USUARIOS_CREDENCIALES_INVALIDAS` | 401 | Credenciales inválidas | El usuario o la contraseña no son correctos. | Inicio de sesión con un usuario inexistente o inactivo, o con una contraseña incorrecta. La respuesta es la misma en todos los casos. Con datos vacíos, el inicio de sesión responde `COMUN_SOLICITUD_INVALIDA` (D-42). |
| `USUARIOS_INICIO_BLOQUEADO` | 429 | Demasiados intentos | Espera unos minutos y vuelve a intentarlo. | Inicio de sesión con un nombre de usuario que tuvo 5 intentos fallidos seguidos, exista o no; el bloqueo dura 15 minutos y la respuesta lleva `Retry-After` (D-60). |
| `ROLES_NOMBRE_REPETIDO` | 409 | Nombre repetido | Ya existe un rol con ese nombre, o con uno que solo cambia en mayúsculas, tildes o signos. Elige otro. | Crear o renombrar un rol con un nombre que da el mismo identificador que otro, incluidos los 10 de D-16. |
| `ROLES_ROL_PREDEFINIDO` | 409 | Rol de la matriz D-16 | Los roles de la matriz D-16 no se pueden cambiar ni borrar. Crea un rol nuevo con los permisos que necesitas. | Editar o borrar uno de los 10 roles de D-16 (D-63). |
| `ROLES_ROL_ASIGNADO` | 409 | Rol asignado | El rol está asignado a usuarios. Quítaselo antes de borrarlo. | Borrar un rol asignado. La pantalla muestra a cuántos usuarios. |
| `ROLES_SIN_ADMINISTRADOR` | 409 | Sin administrador | El cambio dejaría al sistema sin nadie que administre los roles. | Un cambio de los roles de un usuario, o la edición de un rol, quitaría el último `USUARIOS_ROLES:ESCRITURA` o se lo quitaría a quien hace el cambio. |
| `ROLES_PERIODO_CERRADO` | 409 | Periodo cerrado | El periodo está cerrado y ya no admite cambios. | Designar al Responsable de consolidación de un periodo cerrado (F05-H03). |
| `NORMATIVA_VERSION_EN_USO` | 409 | Versión en uso | La versión rige al menos un periodo y ya no se puede cambiar. Crea una versión nueva a partir de ella. | Editar una versión de normativa asociada a un periodo (RF-19, F04-H02). |
| `NORMATIVA_CODIGO_REPETIDO` | 409 | Código repetido | Ya existe una versión de normativa con ese código. Elige otro. | Crear una versión, o editar su cabecera, con el código de otra versión. |
| `NORMATIVA_PERIODO_CON_VERSION` | 409 | Periodo con versión | El periodo ya tiene una versión de normativa. | Asociar una versión a un periodo que ya tiene otra. |
| `ACADEMICO_CODIGO_REPETIDO` | 409 | Código repetido | Ya existe un periodo con ese código. Elige otro. | Registrar un periodo académico con el código de otro (F02-H01). |
| `ACADEMICO_PERIODO_CERRADO` | 409 | Periodo cerrado | El periodo está cerrado y ya no admite cambios. | Corregir, abrir o cambiar el estado de un periodo cerrado (RF-13). |
| `ACADEMICO_TRANSICION_NO_PERMITIDA` | 409 | Cambio de estado no permitido | El periodo solo pasa al estado siguiente, sin saltos ni retrocesos. | Pedir para un periodo un estado que no es el siguiente de Planificación, En aprobación, Vigente y Cerrado. |
| `ACADEMICO_PERIODO_SIN_VERSION` | 409 | Periodo sin versión | El periodo necesita su versión de normativa para salir de Planificación. Ábrelo antes. | Pasar a En aprobación un periodo sin versión de normativa. |
| `ACADEMICO_PERIODO_CON_VERSION` | 409 | Periodo con versión | El periodo ya tiene otra versión de normativa, y no se puede cambiar. | Abrir con otra versión un periodo que ya tiene una (D-69). |
| `ACADEMICO_UNIDAD_REPETIDA` | 409 | Unidad repetida | Ya existe una unidad con ese código. Elige otro. | Registrar una unidad de la estructura orgánica con el código de otra (F03-H01). |
| `ACADEMICO_SEDE_MATRIZ_EXISTENTE` | 409 | Sede matriz existente | La institución ya tiene su sede matriz. Registra las demás como sede, extensión o campus. | Registrar una segunda sede matriz. |
| `ACADEMICO_UNIDAD_CON_DEPENDIENTES` | 409 | Unidad con dependientes | La unidad tiene unidades activas que dependen de ella. Inactívalas antes. | Inactivar una unidad con unidades activas debajo (F03-H01). |
| `ACADEMICO_CARRERA_REPETIDA` | 409 | Carrera repetida | Ya existe una carrera con ese código. Revisa el código SENESCYT. | Registrar una carrera con el código de otra (F03-H02). |
| `ACADEMICO_SIGLAS_REPETIDAS` | 409 | Siglas repetidas | Otra carrera ya usa esas siglas. Elige otras. | Registrar o corregir una carrera con las siglas de otra. |
| `ACADEMICO_MALLA_REPETIDA` | 409 | Malla repetida | Ya existe una malla con ese código de versión. Elige otro. | Registrar una malla con el código de versión de otra. |
| `ACADEMICO_ASIGNATURA_REPETIDA` | 409 | Asignatura repetida | Ya existe una asignatura con ese código. Elige otro. | Registrar una asignatura con el código de otra. |
| `ACADEMICO_ASIGNATURA_PARALELO_REPETIDA` | 409 | Asignatura-paralelo repetida | Esa asignatura ya está en ese paralelo del periodo. Si está retirada, vuelve a ofertarla. | Ofertar una asignatura en un paralelo donde ya está, ofertada o retirada (F03-H03). |
| `ACADEMICO_OFERTA_CERRADA` | 409 | Oferta cerrada | La oferta solo cambia mientras el periodo está en Planificación. | Ofertar, corregir, retirar o volver a ofertar con el periodo en En aprobación, Vigente o Cerrado (F03-H03). |
| `CARGAS_FORMATO_NO_ADMITIDO` | 400 | Formato no admitido | Solo se admiten archivos CSV y XLSX. Descarga la plantilla de la carga y guárdala en uno de esos formatos. | Subir un archivo de carga que no termina en `.csv` ni `.xlsx`, o cuyo contenido no corresponde a su extensión, como un XLS antiguo renombrado (F01-H02). |
| `CARGAS_CODIFICACION_NO_ADMITIDA` | 400 | Codificación no admitida | El CSV tiene que estar en UTF-8. Guárdalo como «CSV UTF-8» y vuelve a subirlo. | Subir un CSV que no es UTF-8 válido, por ejemplo uno en Windows-1252 con tildes. |
| `CARGAS_VARIAS_HOJAS` | 400 | Varias hojas | El archivo XLSX tiene que tener una sola hoja, con los encabezados en la primera fila. | Subir un XLSX con más de una hoja. |
| `CARGAS_ARCHIVO_ILEGIBLE` | 400 | Archivo ilegible | El archivo no se puede leer. Revisa el detalle, corrígelo y vuelve a subirlo. | Comillas sin cerrar, una fila con otro número de valores que el encabezado o un XLSX dañado o cifrado. Un detalle `archivo` dice la fila; nunca el valor. |
| `CARGAS_ENCABEZADOS_DISTINTOS` | 400 | Encabezados distintos de la plantilla | Las columnas del archivo no son las de la plantilla de la carga, en su orden. Revisa las columnas marcadas. | Faltan, sobran, se repiten o están fuera de lugar columnas de la plantilla. Un detalle por columna: «Falta en el archivo.», «No está en la plantilla.», «Está repetida.» o «Está fuera de lugar: va en la posición N.». |
| `CARGAS_ARCHIVO_SIN_REGISTROS` | 400 | Archivo sin registros | El archivo no tiene registros debajo de los encabezados. | Subir un archivo vacío o con solo los encabezados. |
| `CARGAS_ARCHIVO_DEMASIADO_GRANDE` | 413 | Archivo demasiado grande | El archivo pasa de 5 MB, el tamaño máximo de una carga. | Subir un archivo de carga de más de 5 MB. Más de 10 MB lo corta el proceso con `COMUN_CONTENIDO_DEMASIADO_GRANDE`. |
| `COMUN_ERROR_INTERNO` | 500 | Error inesperado | Ocurrió un error inesperado. Intenta de nuevo en unos minutos; si el problema sigue, informa el identificador del incidente. | Excepción técnica no reconocida (por ejemplo, la base de datos no responde), o de dominio o de aplicación sin código en el catálogo. Siempre con `idIncidente`; nunca con trazas, clases, SQL ni el mensaje original. |
| `COMUN_SOLICITUD_INVALIDA` | 400 | Solicitud inválida | Revisa los campos marcados y vuelve a intentarlo. | Uno o más campos no cumplen el contrato. Con `detalles`, uno por campo; también sin `detalles`, para otros errores 4xx del framework sin código propio. |
| `COMUN_CUERPO_ILEGIBLE` | 400 | Solicitud ilegible | El contenido enviado no tiene un formato válido. Revisa los datos y vuelve a intentarlo. | El cuerpo no es JSON válido o no tiene la forma que espera la operación. |
| `COMUN_RECURSO_NO_ENCONTRADO` | 404 | Recurso no encontrado | La dirección solicitada no existe. Revisa la dirección y vuelve a intentarlo. | La ruta no existe. Sin token, el 401 llega antes. |
| `COMUN_METODO_NO_PERMITIDO` | 405 | Operación no permitida | Esta dirección no admite la operación solicitada. | La ruta existe, pero no con ese método HTTP. |
| `COMUN_FORMATO_NO_ACEPTADO` | 406 | Formato no disponible | La respuesta no está disponible en el formato solicitado. | El cliente pide un formato (`Accept`) que la operación no produce. |
| `COMUN_CONTENIDO_DEMASIADO_GRANDE` | 413 | Contenido demasiado grande | El contenido enviado supera el tamaño máximo que admite el sistema. | El cuerpo supera el máximo del proceso, por ejemplo un archivo de carga de más de 10 MB (F01-H02). Un archivo de carga de más de 5 MB responde `CARGAS_ARCHIVO_DEMASIADO_GRANDE`. |
| `COMUN_TIPO_NO_SOPORTADO` | 415 | Tipo de contenido no soportado | El contenido enviado está en un tipo que esta operación no acepta. | El cuerpo viene con un `Content-Type` que la operación no acepta. |
| `COMUN_SERVICIO_NO_DISPONIBLE` | 503 | Servicio no disponible | El servicio no está disponible en este momento. Intenta de nuevo en unos minutos. | El API Gateway no puede conectar con el proceso de la ruta (D-40). |
| `COMUN_EVENTO_NO_RECONOCIDO` | 400 | Evento no reconocido | El receptor no admite este tipo de evento. | Un receptor de eventos entre procesos (`/interno/<servicio>/eventos`) recibe un evento cuyo `tipo` no tiene manejador. No lo registra, y el emisor deja la publicación pendiente (ADR-018). |

- Los prefijos `COMUN_` y `SEGURIDAD_` son de la plataforma: los usan todos los procesos y el API Gateway. Los demás códigos llevan el prefijo de su servicio.
- Un código no se renombra ni se reutiliza. Cada fila coincide con el catálogo del código (`CodigosComunes` o `Errores<Servicio>`), y una prueba lo comprueba (ADR-016).
- Para registrar un error de un servicio, ver `backend/plantillas/README.md`.
